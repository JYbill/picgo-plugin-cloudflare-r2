# 测试类型选择

按测试实际触达的内容判断类型，不只看文件名或开发者给它的标签。

```text
[定位风险]
      |
      +-- 纯逻辑 / 校验 / 分支 / 错误处理 / 本地 service
      |       -> 单元测试
      |
      +-- 真实数据库 / Redis / 网络 / 文件系统 / 队列 / 框架边界
      |       -> 集成测试
      |
      +-- HTTP / CLI / 消息入口 / 公开 SDK 的完整调用流程
              -> 端到端测试
```

## 单元测试

用于验证纯逻辑、校验规则、分支、错误处理和本地 service 行为。除非被测对象本身就是对应的基础设施工具，否则不访问真实数据库、网络、队列、缓存、文件系统或第三方 API。

## 集成测试

用于验证代码与真实依赖、真实框架边界能否协同工作。优先使用真实依赖，不 mock 正在被集成验证的部分。共享基础设施默认只读；需要写入时，使用隔离数据并在测试后清理。

## 端到端测试

通过真实公开入口验证完整流程，例如 HTTP、CLI、消息入口或公开 SDK。使用隔离测试环境和最少必要数据，测试后清理或重建状态。

## 范围控制

- 能用单元测试直接证明行为时，不升级成集成测试或端到端测试。
- 真实风险位于框架、序列化、持久化或外部协议边界时，不用单元测试的 mock 交互伪装信心。
- 修改后先运行最小相关测试；只在共享行为、公开契约或基础设施受影响时扩大到整组验证。
